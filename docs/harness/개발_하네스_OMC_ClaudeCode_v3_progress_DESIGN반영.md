# 스마트 점검 리포트 개발 문서

> 대상 프로젝트: 스마트 점검 리포트  
> 개발 방식: OMC + Claude Code 세션 분할 개발  
> 기술 스택: Vue 3 + Vite + Tailwind CSS / Node.js + Express / SQLite + better-sqlite3 / GPT API  
> 목적: 발표용 데모이지만 DB, API, AI, 리포트 생성, PDF, 공유 링크, 비교 기능까지 실제 동작하는 수준으로 구현

---

# 개발 하네스 - OMC / Claude Code 세션용

## 1. 목적

이 하네스는 OMC와 Claude Code를 사용하여 스마트 점검 리포트를 세션 단위로 안정적으로 구현하기 위한 실행 기준 문서이다.

각 세션은 다음 원칙을 따라야 한다.

1. 세션별 담당 범위만 구현한다.
2. 이전 세션 산출물을 먼저 확인한다.
3. 구현 후 반드시 실행 및 검증 명령을 남긴다.
4. API 계약과 DB schema 변경은 문서에 반영한다.
5. 다음 세션이 이어받을 수 있도록 종료 보고를 작성한다.

---

## 2. 공통 컨텍스트 패킷

새로운 Claude Code 세션을 시작할 때 반드시 아래 내용을 컨텍스트로 제공한다.

```md
# 프로젝트 컨텍스트

프로젝트명: 스마트 점검 리포트

기술 스택:
- frontend: Vue 3 + Vite + Tailwind CSS
- backend: Node.js + Express
- DB: SQLite + better-sqlite3
- AI: GPT API
- 이미지: Base64를 SQLite에 저장
- PDF: HTML 템플릿 + window.print()

핵심 정책:
- 로그인 없음, 데모 사용자 선택 방식
- selectedUserId, selectedRole을 localStorage에 저장
- API 요청 시 userId 전달
- 백엔드에서 DB 기준 권한 확인
- 점검 제출 시 리포트 자동 생성
- Report는 생성 시점 snapshot JSON으로 저장
- 생성 완료 리포트는 수정/삭제 불가
- 수정 필요 시 새 리포트 생성
- AI는 법적 판단/이미지 판독/보증금 공제 판단을 하지 않음
- AI 응답은 JSON
- 공유 링크는 시공업자/임대인/임차인 모두 생성 가능
- 공유 링크 만료 없음
- 공유 링크 화면에서 이름 마스킹하지 않음
- 리포트 비교는 같은 호실 + 같은 점검 유형, 수리 전/후 예외 허용
```

## DESIGN.md 스타일 시스템 확인 지시

프론트엔드 관련 세션은 구현 전 반드시 `docs/DESIGN.md`를 확인해야 한다.

### 적용 대상

| 세션 | DESIGN.md 확인 필요 여부 |
|---|---|
| F01 - 프론트 기본 세팅 | 필수 |
| F02 - 데모 사용자 선택 및 시공업자 시작 화면 | 필수 |
| F03 - 전체 점검 UI | 필수 |
| F04 - 문제 항목 점검 UI | 필수 |
| F05 - AI 점검 도우미 및 최종 의견 | 필수 |
| F06 - 이미지 첨부 | 필수 |
| F07 - 리포트 목록/상세/확인 | 필수 |
| F08 - 리포트 비교, 공유 링크, PDF | 필수 |
| 백엔드 세션 | 선택 사항 |

### 스타일 적용 원칙

프론트엔드는 `docs/DESIGN.md`의 Tesla-inspired Design System을 기반으로 구현한다.

단, 이 프로젝트는 차량 홍보 페이지가 아니라 임대차 점검 리포트 웹앱이므로, DESIGN.md를 그대로 복제하지 않고 다음 기준으로 적용한다.

1. **색상 체계**
   - Primary CTA는 Electric Blue `#3E6AE1`를 사용한다.
   - 기본 배경은 Pure White `#FFFFFF`를 우선한다.
   - 보조 표면은 Light Ash `#F4F4F4`를 사용한다.
   - 주요 텍스트는 Carbon Dark `#171A20`를 사용한다.
   - 본문 텍스트는 Graphite `#393C41`를 사용한다.
   - 보조 텍스트는 Pewter `#5C5E62`를 사용한다.

2. **UI 장식 최소화**
   - 불필요한 그림자, 그라데이션, 과한 테두리, 복잡한 장식 요소를 사용하지 않는다.
   - 카드 UI는 최대한 평면적으로 구현한다.
   - 정보 구분은 그림자보다 여백, 정렬, 얇은 구분선, 상태 태그로 처리한다.

3. **버튼**
   - Primary Button은 Electric Blue 배경과 흰색 텍스트를 사용한다.
   - Secondary Button은 흰색 배경과 Graphite 텍스트를 사용한다.
   - 버튼 radius는 기본적으로 4px 또는 Tailwind `rounded` 수준으로 유지한다.
   - 과한 pill 형태 버튼은 피한다.

4. **타이포그래피**
   - 실제 Universal Sans 폰트 파일은 사용하지 않는다.
   - CSS font-family는 `-apple-system, BlinkMacSystemFont, "Segoe UI", "Noto Sans KR", Arial, sans-serif`를 사용한다.
   - 제목은 500~600 weight를 사용하고, 과도한 bold 사용은 피한다.
   - 본문과 UI 텍스트는 14px 중심으로 구성한다.

5. **레이아웃**
   - 와이어프레임의 모바일 우선 카드형 UX를 유지한다.
   - Tesla식 full-viewport hero는 마케팅 랜딩 영역에만 참고하고, 점검 작성 화면에는 적용하지 않는다.
   - 점검 작성 화면은 한 화면 한 작업 원칙을 우선한다.
   - PC에서는 목록/상세/비교 화면을 2열 이상으로 확장할 수 있다.

6. **AI 점검 도우미 카드**
   - AI 결과는 긴 문단보다 행동형 카드로 표시한다.
   - 카드 액션은 `촬영`, `확인`, `참고`, `초안 적용`처럼 짧고 명확하게 구성한다.
   - AI 카드에도 과도한 색상 다양성을 사용하지 않는다.

7. **리포트 화면**
   - 리포트는 흰색 문서형 레이아웃을 사용한다.
   - PDF 출력 시 버튼, 내비게이션, 입력 폼은 숨긴다.
   - 표, 사진, 의견 영역은 정보가 명확하게 읽히도록 여백 중심으로 구성한다.

10. 다음 권장 세션

### 금지 사항

- 기존 progress 내용을 삭제하지 않는다.
- 실패나 보류 사항을 숨기지 않는다.
- 담당 세션 범위를 넘어 대규모 수정하지 않는다.
- progress.md를 갱신하지 않고 세션을 종료하지 않는다.

### 세션 시작 공통 문장

```md
작업 시작 전 반드시 `docs/progress.md`를 먼저 확인해줘.
현재까지 완료된 세션, 보류된 이슈, 다음 세션 인수인계 내용을 확인한 뒤 이번 세션 범위만 작업해줘.
```

### 세션 종료 공통 문장

```md
작업 종료 후 반드시 `docs/progress.md`를 갱신해줘.
이번 세션의 상태를 전체 진행 현황 표에 반영하고, 세션별 요약 기록에 이번 작업 내용을 추가해줘.
수정 파일, 실행 명령, 검증 결과, 실패/보류/TODO, 다음 세션 인수인계를 반드시 포함해줘.
```
