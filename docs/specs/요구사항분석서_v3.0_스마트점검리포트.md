# 1. 문서 목적

본 문서는 스마트 점검 리포트 기능의 수정된 요구사항을 정리하기 위한 요구사항 분석서이다. 기존 요구사항명세서 v2.2에서 정의한 반응형 웹, 시공업자·임대인·임차인 역할, 이미지 첨부, 웹/PDF 리포트, 공유 링크, 리포트 누적 목록의 기본 구조는 유지한다.

다만 최근 논의된 UX 개선안에 따라 시공업자 점검 흐름을 “전체 점검”과 “문제 항목 점검”으로 단순화하고, AI 기능을 법률 판단 또는 이미지 결함 판독이 아닌 “점검 기록 보조” 기능으로 재정의한다.

본 문서는 개발 지시서가 아니라 팀원 및 이해관계자와 기능 방향을 합의하고, 이후 기능명세서·PRD·와이어프레임·검증 시나리오를 작성하기 위한 기준 문서로 사용한다.

# 2. 서비스 개요

스마트 점검 리포트는 시공업자가 임대 물건의 상태를 표준화된 방식으로 점검하고, 점검 결과를 사진·상태값·전문 의견과 함께 리포트로 생성하여 임대인과 임차인이 같은 자료를 확인할 수 있도록 하는 웹 기반 기능이다.

| 구분 | 내용 |
| --- | --- |
| 서비스 형태 | 반응형 웹사이트 |
| 지원 환경 | 모바일 웹, PC 웹 |
| 주요 사용자 | 시공업자, 임대인, 임차인, 공유 링크 접근자 |
| 핵심 기능 | 점검 작성, 공간/문제 항목별 기록, 이미지 첨부, AI 점검 도우미, 리포트 생성, PDF 내보내기, 공유 링크, 확인 완료, 리포트 비교 |
| AI 역할 | 점검자가 빠뜨리기 쉬운 확인 질문, 사진 촬영 기준, 필요 자료, 중립적 전문 의견 초안 제공 |
| AI 제외 범위 | 법적 책임 판단, 보증금 공제 판단, 이미지 자동 결함 판독, 판례 자동 검색, 소송 문서 작성 |

# 3. 서비스 배경 및 필요성

임대차 관리 과정에서는 입주 전 상태, 정기 관리 이력, 퇴거 전후 하자 여부, 긴급 수리 필요성 등을 둘러싸고 임대인과 임차인 간 분쟁이 발생할 수 있다.

기존에는 사진을 메신저로 주고받거나 구두로 설명하는 경우가 많아 사진이 어떤 항목의 증빙인지, 언제 어떤 상태였는지, 이전 기록과 어떻게 다른지 확인하기 어렵다.

| 기존 문제 | 설명 | 수정 요구 방향 |
| --- | --- | --- |
| 기록의 객관성 부족 | 상태가 표준화된 항목으로 남지 않음 | 공간/항목/상태/사진을 연결하여 기록 |
| 사진 관리 어려움 | 사진이 어떤 하자 또는 위치의 증빙인지 불명확함 | 사진별 설명과 항목 연결 제공 |
| 점검 흐름 복잡성 | 모든 점검을 같은 방식으로 작성하면 현장 사용성이 떨어짐 | 입주 전·정기점검은 전체 점검, 퇴거·긴급·수리점검은 문제 항목 점검으로 분리 |
| 분쟁 시 자료 부족 | 입주 전 기록, 수리 내역, 이전 점검과 비교하기 어려움 | AI 점검 도우미가 추가 확인 자료와 촬영 기준 안내 |
| 책임 판단 위험 | AI가 법적 판단을 하면 신뢰·책임 문제가 발생함 | AI는 기록 보조로 제한하고 최종 의견은 시공업자가 작성 |

# 7. 주요 정책

## 7.1 점검 목적 기반 분기 정책

사용자는 점검 목적만 선택한다. 시스템은 선택된 목적에 따라 입주 전·정기점검은 전체 점검 흐름으로, 퇴거 전·후·긴급·수리 전·후 점검은 문제 항목 점검 흐름으로 자동 분기한다.

## 7.2 전체 점검 정책

전체 점검은 현장 동선에 맞춰 현관, 거실, 주방, 욕실, 안방 등 공간별로 빠르게 상태를 확인한다. 모든 항목을 상세 작성하지 않고 정상/주의/수리 필요 중 선택한 뒤, 주의 또는 수리 필요 항목만 상세 기록한다.

## 7.3 문제 항목 점검 정책

문제 항목 점검은 특정 문제의 분야, 항목, 위치, 증상 설명, 현장 확인 항목, 사진, 전문 의견을 집중적으로 기록한다. 예: 퇴거 전 점검 > 설비·배관 > 누수 확인.

## 7.4 AI 점검 도우미 정책

AI는 기록 보조자 역할만 수행한다. 사진 촬영 기준, 추가 확인 질문, 필요 자료, 표현 주의, 전문 의견 초안을 제공하되 법적 책임을 단정하지 않는다.

## 7.5 리포트 공개 정책

작성 중 및 제출 완료 상태의 점검은 시공업자에게만 보인다. 리포트 생성 이후부터 임대인과 임차인이 확인할 수 있다.

## 7.6 리포트 수정/삭제 정책

작성 중 및 제출 완료 점검은 시공업자가 삭제할 수 있다. 생성 완료 리포트는 직접 수정하거나 삭제하지 않고, 필요 시 새 리포트를 생성한다.

## 7.7 공유 링크 정책

공유 링크는 이미 생성된 리포트에 접근하기 위한 URL이다. 1차 구현에서는 만료 시간, 로그인, 비밀번호를 두지 않는다.

## 7.8 PDF 내보내기 정책

PDF는 웹 리포트를 HTML 템플릿으로 렌더링한 뒤 브라우저 인쇄 또는 PDF 저장 방식으로 내보낸다. 확인 버튼, 공유 버튼, 화면용 내비게이션은 PDF에 포함하지 않는다.

리포트 상세를 확인한다.

필요 시 PDF 저장 또는 공유 링크 복사를 수행한다.

같은 호실의 이전 리포트와 현재 리포트를 비교한다.

임차인이 본인 호실 리포트 목록을 확인한다.

리포트 상세에서 점검 항목과 사진을 확인한다.

의견 저장 후 확인 완료 처리한다.

## UC-05. 공유 링크 접근자가 리포트를 조회한다

공유 링크를 통해 리포트에 접근한다.

리포트 본문을 확인한다.

필요 시 PDF를 저장한다.

# 18. 요구사항 요약

스마트 점검 리포트는 반응형 웹 기반으로 구현한다.

데모에서는 로그인/회원가입 없이 역할 선택 화면을 사용한다.

시공업자는 점검 목적을 선택하고, 시스템은 전체 점검 또는 문제 항목 점검으로 자동 분기한다.

입주 전·정기점검은 공간별 빠른 체크와 이상 항목 상세 기록으로 구성한다.

퇴거 전·후, 긴급, 수리 전·후 점검은 특정 문제를 깊게 기록하는 문제 항목 점검으로 구성한다.

AI 점검 도우미는 법적 판단이 아니라 촬영, 확인, 의견 작성으로 이어지는 행동 카드만 제공한다.

AI는 이미지 결함 판독, 판례 자동 검색, 보증금 공제 판단을 수행하지 않는다.

시공업자는 AI 초안을 검토·수정하여 최종 전문 의견을 작성한다.

리포트는 생성 완료 이후 임대인과 임차인에게 공개된다.

임대인은 통합 목록, 상세 확인, PDF 저장, 공유 링크, 리포트 비교를 사용할 수 있다.

임차인은 본인 호실 리포트를 확인하고 필요한 경우 의견을 남길 수 있다.

PDF 리포트는 표지, 점검 요약, 체크리스트 결과, 사진 증빙, 확인 및 이력 정보로 구성한다.

리포트는 법적 책임 판단 문서가 아니라 점검 당시 상태와 증빙을 정리하는 자료로 명시한다.

생성 완료 리포트는 직접 수정/삭제하지 않고, 필요 시 새 리포트를 생성한다.
