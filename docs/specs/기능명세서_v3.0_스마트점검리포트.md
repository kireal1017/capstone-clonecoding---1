# 기능명세서 v3.0 - 스마트 점검 리포트

## 1. 문서 목적

본 문서는 스마트 점검 리포트 기능을 실제 개발 가능한 수준으로 구체화하기 위한 기능명세서이다.

기존 기능명세서 v2.2의 구조를 유지하되, 최근 수정된 요구사항과 와이어프레임을 반영하여 다음 내용을 보완한다.

- 시공업자 화면을 **전체 점검**과 **문제 항목 점검**으로 단순화
- AI 기능을 **법적 판단/이미지 판독**이 아닌 **AI 점검 도우미**로 재정의
- 입주 전·정기점검은 공간별 빠른 체크 중심으로 수정
- 퇴거 전·퇴거 후·긴급·수리 전·수리 후 점검은 문제 항목 중심 기록으로 수정
- 임대인/임차인 확인 흐름과 의견 남기기 흐름 보완
- 리포트 양식을 웹/PDF 공통 템플릿 기준으로 재정리

본 문서는 이후 PRD 작성, 화면 설계, 데이터 구조 설계, 개발 작업 분해, 검증 시나리오 작성의 기준 문서로 사용한다.

| 구분 | 내용 |
|---|---|
| 문서 성격 | PRD 제작 전 단계의 상세 기능명세서 |
| 주요 목적 | 기능 범위, 유스케이스, 상태 규칙, 데이터 구조, 예외 처리를 구체화 |
| 주요 사용자 | 시공업자, 임대인, 임차인, 공유 링크 접근자 |
| 구현 방향 | 반응형 단일 웹 |
| 인증 범위 | 1차 구현에서는 로그인/회원가입 제외, 데모용 역할 선택 사용 |
| 리포트 기준 | 하나의 리포트는 하나의 호실, 하나의 점검 유형, 하나의 점검 흐름을 기준으로 생성 |
| AI 기준 | AI는 법적 책임 판단, 이미지 판독, 비용 산정을 하지 않고 기록 보조만 수행 |

## 2. 기능 개요

스마트 점검 리포트는 시공업자가 임대 물건의 시설 상태를 점검하고, 체크리스트·상황 설명·사진·전문 의견을 기반으로 리포트를 생성하는 기능이다.

시공업자는 점검 목적에 따라 다음 두 가지 흐름 중 하나로 점검을 작성한다.

| 점검 흐름 | 적용 점검 유형 | 목적 |
|---|---|---|
| 전체 점검 | 입주 전 점검, 정기 점검 | 집 전체 상태를 공간별로 빠르게 확인하고, 이상 항목만 상세 기록 |
| 문제 항목 점검 | 퇴거 전 점검, 퇴거 후 점검, 긴급 점검, 수리 전 점검, 수리 후 점검 | 누수, 파손, 고장 등 특정 문제를 깊게 기록 |

리포트가 생성되면 임대인과 임차인은 동일한 리포트를 확인할 수 있으며, PDF 내보내기와 공유 링크 접근이 가능하다.

| 구분 | 내용 |
|---|---|
| 서비스 형태 | 반응형 웹사이트 |
| 지원 환경 | 모바일 웹, PC 웹 |
| 구현 방식 | 단일 코드베이스 기반 반응형 UI |
| 주요 사용자 | 시공업자, 임대인, 임차인 |
| 핵심 흐름 | 점검 시작 → 점검 목적 선택 → 대상 입력 → 전체 점검 또는 문제 항목 점검 → AI 점검 도우미 → 사진/의견 작성 → 점검 제출 → 리포트 생성 → 임대인/임차인 확인 |
| 이미지 처리 | 1차 구현에서는 Base64 인코딩 방식 |
| PDF 처리 | HTML 리포트 템플릿 미리보기 후 브라우저 인쇄 또는 PDF 저장 |
| 이력 처리 | 호실 기준 리포트 누적 목록 |
| 비교 처리 | 같은 호실의 이전/현재 리포트 수동 비교 |
| AI 처리 | 사용자가 입력한 텍스트와 선택값을 기반으로 확인 질문, 사진 기준, 필요 자료, 의견 초안 제공 |

## 3. 핵심 정책

### 3.1 반응형 단일 웹 정책

본 기능은 모바일 웹과 PC 웹에서 모두 사용할 수 있어야 한다.

1차 구현에서는 모바일용 코드와 PC용 코드를 분리하지 않고, 하나의 반응형 웹 코드베이스로 구현한다.

| 항목 | 정책 |
|---|---|
| 모바일 웹 | 지원 |
| PC 웹 | 지원 |
| 코드베이스 | 단일 코드베이스 |
| 레이아웃 | 화면 크기에 따라 반응형 전환 |
| 개발 기준 | 모바일 우선 레이아웃을 기본으로 하되 PC 화면에서도 사용 가능해야 함 |

---

### 3.2 점검 목적 선택 정책

사용자는 어려운 내부 용어를 보지 않고, 점검 목적만 선택한다.

| 점검 유형 | 사용자 화면 표현 | 내부 처리 흐름 |
|---|---|---|
| 입주 전 점검 | 입주 전 점검 | 전체 점검 |
| 정기 점검 | 정기 점검 | 전체 점검 |
| 퇴거 전 점검 | 퇴거 전 점검 | 문제 항목 점검 |
| 퇴거 후 점검 | 퇴거 후 점검 | 문제 항목 점검 |
| 긴급 점검 | 긴급 점검 | 문제 항목 점검 |
| 수리 전 점검 | 수리 전 점검 | 문제 항목 점검 |
| 수리 후 점검 | 수리 후 점검 | 문제 항목 점검 |

사용자 화면에는 “전체 상태 기록형”, “문제 집중 기록형” 같은 내부 설계 용어를 노출하지 않는다.

---

### 3.3 전체 점검 정책

전체 점검은 입주 전 점검과 정기 점검에 적용한다.

전체 점검은 임대 물건의 전체 상태를 넓게 확인하는 흐름이며, 공간별 빠른 체크를 기본으로 한다.

| 항목 | 정책 |
|---|---|
| 적용 점검 | 입주 전 점검, 정기 점검 |
| 점검 기준 | 공간별 확인 |
| 기본 입력 | 정상 / 주의 / 수리 필요 |
| 상세 입력 | 주의 또는 수리 필요 항목만 상세 기록 |
| AI 역할 | 누락 방지, 사진 기준 안내, 의견 초안 제공 |
| 주요 목적 | 입주 당시 상태 기준 기록, 정기적 상태 변화 기록 |

공간 예시는 다음과 같다.

| 공간 | 확인 항목 예시 |
|---|---|
| 현관 | 현관문, 도어락, 문틀, 신발장 |
| 거실 | 벽지, 바닥, 창호, 콘센트 |
| 주방 | 싱크대, 배수, 후드, 가스/인덕션 |
| 욕실 | 세면대, 변기, 수전, 배수 |
| 안방/방 | 벽지, 바닥, 창호, 콘센트 |
| 베란다 | 창호, 배수, 바닥, 누수 흔적 |

---

### 3.4 문제 항목 점검 정책

문제 항목 점검은 퇴거 전·후, 긴급, 수리 전·후 점검에 적용한다.

문제 항목 점검은 특정 하자나 문제를 깊게 기록하는 흐름이다.

| 항목 | 정책 |
|---|---|
| 적용 점검 | 퇴거 전, 퇴거 후, 긴급, 수리 전, 수리 후 |
| 점검 기준 | 특정 문제 항목 중심 |
| 기본 입력 | 분야, 세부 항목, 위치, 증상 설명 |
| 현장 확인 | 관찰 가능한 흔적을 시공업자가 직접 선택 |
| AI 역할 | 추가 확인 질문, 촬영 기준, 필요 자료, 의견 초안 제공 |
| 주요 목적 | 분쟁 가능성이 있는 항목에 대한 객관적 기록 보조 |

문제 항목 예시는 다음과 같다.

| 분야 | 문제 항목 예시 |
|---|---|
| 설비·배관 | 누수, 배수 불량, 수전 흔들림, 보일러 이상 |
| 인테리어·마감 | 벽지 찢어짐, 바닥 찍힘, 몰딩 파손 |
| 샷시·창호 | 방충망 찢어짐, 유리 파손, 실리콘 들뜸 |
| 전기 | 콘센트 불량, 조명 미작동, 차단기 이상 |
| 도어·잠금 | 도어락 불량, 경첩 파손, 문틀 뒤틀림 |
| 가전·옵션 | 에어컨 미작동, 세탁기 누수, 냉장고 고장 |

---

### 3.5 AI 점검 도우미 정책

AI 점검 도우미는 사용자의 입력값을 바탕으로 시공업자의 기록을 보조하는 기능이다.

AI는 다음을 수행한다.

| AI 제공 내용 | 설명 |
|---|---|
| 누락 확인 | 점검 항목에서 추가로 확인해야 할 내용을 안내 |
| 사진 촬영 기준 | 전체 사진, 근접 사진, 크기 기준 사진, 전후 사진 등 안내 |
| 필요 자료 안내 | 입주 전 리포트, 이전 수리 내역, 임차인 신고 기록 등 안내 |
| 표현 주의 안내 | 책임 소재를 단정하지 않는 문장 방향 안내 |
| 전문 의견 초안 | 시공업자가 수정 가능한 중립적 의견 초안 생성 |

AI는 다음을 수행하지 않는다.

| 제외 항목 | 사유 |
|---|---|
| 이미지 직접 판독 | 1차 구현 범위에서 제외, 비용·시간·정확도 부담 |
| 법적 책임 판단 | 법률 자문으로 오해될 수 있음 |
| 임차인 고의 판단 | 고의·과실 판단은 법적 판단 영역 |
| 임대인 수선 책임 판단 | 계약서, 이전 기록, 수리 내역 등 종합 판단 필요 |
| 보증금 공제 금액 산정 | 견적, 감가, 계약 내용 등이 필요 |
| 판례 자동 검색 | 1차 구현 범위에서 제외 |
| 소송 대응 문서 작성 | 법률 서비스로 오해될 수 있음 |

AI가 제공하는 모든 문구는 “최종 판단”이 아니라 “기록 보조”로 표시한다.

---

### 3.6 현장 확인 항목 선택 정책

문제 항목 점검에서 시공업자는 현장에서 관찰 가능한 항목을 직접 선택한다.

AI가 자동으로 판정하지 않는다.

| 선택값 | 의미 |
|---|---|
| 있음 | 시공업자가 육안 또는 현장 정보로 확인 |
| 없음 | 시공업자가 육안 또는 현장 정보로 확인되지 않음 |
| 확인 필요 | 현재 정보만으로 확인이 어려움 |

예시 항목은 다음과 같다.

| 관찰 항목 | 설명 |
|---|---|
| 외부 충격 흔적 | 찌그러짐, 깨짐, 찍힘 등 외부 충격으로 보이는 흔적 |
| 부식·노후 흔적 | 녹, 변색, 경화, 균열 등 노후화 흔적 |
| 연결부 이상 | 느슨함, 흔들림, 틈, 물방울 맺힘 |
| 누수 확산 흔적 | 벽·천장·바닥 젖음, 곰팡이, 물고임 |
| 최근 수리 이력 | 최근 교체·수리·보수 여부 |
| 입주 전 동일 기록 | 같은 위치의 이전 사진 또는 리포트 존재 여부 |
| 임차인 신고 기록 | 이전 신고·요청 기록 존재 여부 |

---

### 3.7 이미지 첨부 정책

1차 구현에서는 이미지를 Base64로 인코딩하여 첨부한다.

| 항목 | 정책 |
|---|---|
| 사용자 표현 | 사진 첨부 |
| 기술 방식 | Base64 인코딩 |
| 저장 위치 | 클라이언트 저장소 또는 로컬 DB 기준 |
| 리포트 반영 | 웹 리포트와 PDF 내보내기 대상에 포함 |
| 향후 확장 | 서버 파일 저장 또는 클라우드 스토리지 저장으로 확장 가능 |

사진은 항목별로 연결되어야 하며, 사진별 설명을 입력할 수 있어야 한다.

AI는 이미지 자체를 분석하지 않고, 어떤 사진을 촬영해야 하는지 안내한다.

---

### 3.8 리포트 공개 정책

작성 중 또는 제출 완료 상태의 점검은 시공업자에게만 보인다.

리포트가 생성된 이후부터 임대인과 임차인이 해당 리포트를 확인할 수 있다.

| 상태 | 시공업자 | 임대인 | 임차인 |
|---|---|---|---|
| 작성 중 | 가능 | 불가 | 불가 |
| 제출 완료 | 가능 | 불가 | 불가 |
| 리포트 생성 완료 | 가능 | 가능 | 가능 |
| 임대인 확인 완료 | 가능 | 가능 | 가능 |
| 임차인 확인 완료 | 가능 | 가능 | 가능 |

공유 링크는 리포트를 공개 상태로 바꾸는 기능이 아니라, 이미 생성된 리포트에 접근하기 위한 URL 생성 기능이다.

---

### 3.9 공유 링크 정책

1차 구현에서는 공유 링크에 만료 시간을 두지 않는다.

| 항목 | 정책 |
|---|---|
| 생성 권한 | 시공업자, 임대인, 임차인 모두 가능 |
| 접근 방식 | 링크를 알고 있으면 접근 가능 |
| 만료 시간 | 없음 |
| 로그인 요구 | 없음 |
| 비밀번호 요구 | 없음 |
| 공유 상태값 | 별도로 관리하지 않음 |

실제 서비스에서는 로그인 기반 접근, 비밀번호 보호 링크, 만료 링크, 서버 토큰 검증 등을 검토할 수 있다.

---

### 3.10 PDF 내보내기 정책

PDF는 별도 서버 PDF 엔진을 사용하지 않고, HTML 리포트 템플릿을 기반으로 내보내기 한다.

| 단계 | 설명 |
|---|---|
| 1단계 | 점검 데이터를 기반으로 HTML 리포트 템플릿 렌더링 |
| 2단계 | 웹 화면에서 리포트 미리보기 |
| 3단계 | 브라우저 인쇄 또는 PDF 저장 방식으로 PDF 내보내기 |

PDF에 포함되는 영역은 리포트 본문이며, 확인 완료 버튼, 공유 버튼, 화면용 내비게이션은 PDF에 포함하지 않는다.

---

### 3.11 리포트 삭제 및 수정 정책

1차 구현에서는 리포트 생성 완료 이후의 삭제 기능을 제공하지 않는다.

| 상태 | 삭제 가능 여부 | 설명 |
|---|---|---|
| 작성 중 | 가능 | 아직 공개 전이므로 시공업자가 삭제 가능 |
| 제출 완료 | 가능 | 리포트 생성 전이므로 시공업자가 삭제 가능 |
| 리포트 생성 완료 | 불가 | 생성 완료 리포트 삭제는 1차 구현에서 보류 |
| 확인 완료 이후 | 불가 | 생성 완료 이후이므로 삭제 불가 |

생성 완료된 리포트는 직접 수정하지 않는다.

수정 또는 재작성 필요 시 시공업자는 새 리포트를 생성한다.

---

### 3.12 리포트 누적 목록 정책

생성된 리포트는 호실 기준으로 누적 저장한다.

| 항목 | 정책 |
|---|---|
| 저장 기준 | 호실 기준 |
| 표시 방식 | 단순 리포트 누적 목록 |
| 별도 House Log DB | 1차 구현 제외 |
| 향후 확장 | House Log, 변경 이력, 자동 비교 기능 등으로 확장 가능 |

---

### 3.13 리포트 비교 정책

리포트 비교는 같은 호실의 리포트 2개를 기준으로 제공한다.

| 항목 | 정책 |
|---|---|
| 비교 대상 | 리포트 2개 |
| 조건 1 | 같은 호실 |
| 조건 2 | 같은 공간 또는 같은 점검/수리 분야 |
| 비교 방식 | PC에서는 좌우 분할, 모바일에서는 상하 분할 |
| 자동 분석 | 제공하지 않음 |
| Change Log 자동 생성 | 제공하지 않음 |

비교 기능은 자동 책임 판단을 하지 않고, 이전 기록과 현재 기록을 함께 확인하는 수동 비교 기능이다.

---

### 3.14 임차인 의견 정책

임차인은 본인 호실 리포트를 확인한 뒤 의견을 남길 수 있다.

| 항목 | 정책 |
|---|---|
| 의견 작성 권한 | 임차인 |
| 의견 작성 시점 | 리포트 상세 확인 후 |
| 의견 유형 | 기존 상태로 확인, 추가 확인 요청, 이견 있음 |
| 의견 내용 | 자유 텍스트 |
| 이미지 첨부 | 선택 가능 |
| 리포트 수정 여부 | 임차인 의견은 원본 리포트를 직접 수정하지 않음 |
| 저장 방식 | 확인 이력과 함께 별도 저장 |

임차인 의견은 리포트 본문을 대체하지 않고, 확인 이력 또는 의견 이력으로 관리한다.

## 7. 상세 기능명세

### a-01. 데모 역할 선택

#### 기능 설명

로그인/회원가입 없이 데모 시연을 위해 사용자가 역할을 선택하는 기능이다.

#### 입력/선택 항목

| 항목 | 설명 |
|---|---|

| 임대인 선택 | 통합 리포트 리스트 및 비교 흐름으로 진입 |
| 임차인 선택 | 본인 호실 리포트 확인 흐름으로 진입 |

#### 처리 흐름

```
서비스 접속
→ 역할 선택 화면 표시
→ 역할 선택
→ 선택한 역할의 메인 화면으로 이동
```

#### 기능 규칙

| 규칙 | 내용 |
|---|---|
| 로그인 제외 | 현재 데모에서는 계정 인증을 하지 않는다. |
| 역할 상태 유지 | 선택한 역할은 브라우저 상태 또는 세션 상태로 유지할 수 있다. |
| 실제 서비스 확장 | 실제 서비스에서는 로그인 사용자 DB의 role 값을 기준으로 자동 분기한다. |

### a-13. AI 점검 도우미

#### 기능 설명

시공업자가 입력한 점검 목적, 항목, 위치, 상태 설명, 현장 확인 항목을 기반으로 점검 보조 정보를 제공하는 기능이다.

#### 입력 데이터

| 입력값 | 설명 |
|---|---|
| 점검 유형 | 입주 전, 정기, 퇴거 전, 긴급 등 |
| 점검 흐름 | 전체 점검 또는 문제 항목 점검 |
| 공간/분야 | 거실, 욕실, 설비·배관 등 |
| 세부 항목 | 창호, 누수, 벽지 등 |
| 상태 설명 | 시공업자가 입력한 상황 설명 |
| 현장 확인 항목 | 있음/없음/확인 필요 선택값 |
| 사진 첨부 상태 | 현재 첨부된 사진 종류 |

#### 출력 데이터

| 출력값 | 설명 |
|---|---|
| 다음 행동 카드 | 촬영, 확인, 의견 작성 등 바로 실행 가능한 행동 |
| 필요한 사진 | 전체 위치, 근접, 기준물 포함, 전후 사진 등 |
| 추가 확인 자료 | 입주 전 리포트, 수리 내역, 신고 기록 등 |
| 표현 주의 | 책임을 단정하지 않는 문구 안내 |
| 전문 의견 초안 | 시공업자가 수정 가능한 의견 초안 |

#### 기능 규칙

| 규칙 | 내용 |
|---|---|
| 행동형 카드 | 긴 설명이 아니라 촬영/확인/적용 버튼 중심으로 제공한다. |
| 법적 판단 제외 | AI는 법적 책임 소재를 판단하지 않는다. |
| 이미지 판독 제외 | AI는 이미지를 직접 분석하지 않는다. |
| 시공업자 최종 검토 | AI 초안은 시공업자가 수정한 뒤 저장한다. |

## 14. 실제 서비스 확장 방향

### 14.1 로그인 기반 역할 분기

데모에서는 역할 선택 화면을 사용하지만, 실제 서비스에서는 로그인된 사용자 정보를 기준으로 역할을 자동 구분한다.

```
로그인
→ 사용자 ID 조회
→ DB에서 role 확인
→ 시공업자/임대인/임차인 화면 자동 분기
```

---

### 14.2 임대인/임차인 자동 연동

데모에서는 시공업자가 임대인/임차인 정보를 직접 입력한다.

실제 서비스에서는 시공업자가 호실을 선택하면 DB에 등록된 임대인/임차인 정보가 자동 입력되는 방식이 적절하다.

```
시공업자 호실 선택
→ DB에서 호실 정보 조회
→ 연결된 임대인/임차인 자동 표시
→ 시공업자는 점검만 작성
```

---

### 14.3 이미지 저장 방식 고도화

1차 구현에서는 Base64 인코딩 방식으로 이미지를 첨부한다.

실제 서비스에서는 다음 방식으로 확장할 수 있다.

| 확장 방식 | 설명 |
|---|---|
| 서버 파일 저장 | 백엔드 서버에 이미지 파일 저장 |
| 클라우드 스토리지 | S3, Cloudinary, Firebase Storage 등 사용 |
| 이미지 압축 | 업로드 전 이미지 크기 및 용량 최적화 |
| 접근 제어 | 리포트 권한에 따라 이미지 접근 제어 |

---

### 14.4 AI 점검 도우미 고도화

1차 구현에서는 템플릿 기반 안내와 AI 의견 초안을 제공한다.

향후에는 다음 기능을 확장할 수 있다.

| 확장 기능 | 설명 |
|---|---|
| 항목별 가이드 DB | 점검 유형 + 공간 + 문제 항목별 가이드 세분화 |
| 이전 리포트 기반 추천 | 같은 호실의 이전 리포트 참고 |
| 사진 누락 자동 체크 | 업로드된 사진 유형 기준으로 누락 여부 표시 |
| 문장 톤 조절 | 전문적, 간결, 상세 등 의견 초안 톤 선택 |
| 참고 문서 링크 | 법률 판단이 아닌 참고 자료 링크 제공 |

---

### 14.5 공유 링크 보안 고도화

1차 구현에서는 공유 링크 만료 시간을 두지 않는다.

실제 서비스에서는 다음 방식으로 보안을 강화할 수 있다.

| 확장 방식 | 설명 |
|---|---|
| 로그인 기반 접근 | 로그인된 사용자만 리포트 확인 |
| 만료 링크 | 일정 시간이 지나면 링크 접근 차단 |
| 비밀번호 링크 | 공유 링크 접근 시 비밀번호 입력 |
| 서버 토큰 검증 | 서버에서 서명된 토큰 검증 |

### 14.6 정식 House Log 기능

현재는 리포트를 호실 기준 단순 목록으로 누적 저장하는 구조까지만 정의한다.

향후 동일 호실에 여러 리포트가 쌓이면 다음 기능을 확장할 수 있다.

| 기능 | 설명 |
|---|---|
| 호실별 이력 타임라인 | 시간 순서대로 점검 리포트 확인 |
| 이전 리포트 비교 | 이전 점검과 현재 점검 비교 |
| 상태 변화 표시 | 신규 하자, 악화, 개선 여부 표시 |
| 이미지 비교 | 과거 이미지와 현재 이미지 비교 |
| Change Log 생성 | 변경 이력 자동 정리 |

### 14.7 리포트 폐기 처리

1차 구현에서는 생성 완료 리포트 삭제 기능을 보류한다.

실제 서비스에서는 삭제 대신 폐기 또는 무효 처리 방식을 검토할 수 있다.

| 항목 | 설명 |
|---|---|
| 폐기 처리 | 리포트를 목록 기본값에서 숨기되 내부 이력은 보존 |
| 폐기 사유 | 잘못된 호실, 잘못된 점검 유형, 중복 생성 등 |
| 처리 일시 | 폐기 처리 시간 저장 |
| 처리자 | 폐기 처리한 사용자 저장 |
| 접근 제어 | 폐기된 리포트의 공유 링크 접근 차단 여부 결정 |

## 15. 기능명세 요약

본 기능명세서의 핵심은 다음과 같다.

1. 반응형 단일 웹으로 구현한다.
2. 로그인/회원가입은 1차 구현에서 제외한다.
3. 데모용 역할 선택 화면을 제공한다.
4. 사용자는 시공업자, 임대인, 임차인으로 나눈다.
5. 시공업자는 새 점검을 시작하고 점검 목적을 선택한다.
6. 입주 전·정기점검은 전체 점검으로 처리한다.
7. 전체 점검은 공간별 빠른 체크를 기본으로 한다.
8. 주의 또는 수리 필요 항목만 상세 기록한다.
9. 퇴거 전·퇴거 후·긴급·수리 전·수리 후 점검은 문제 항목 점검으로 처리한다.
10. 문제 항목 점검은 분야, 위치, 증상 설명, 현장 확인 항목을 기록한다.
11. 현장 확인 항목은 시공업자가 직접 있음/없음/확인 필요로 선택한다.
12. AI 점검 도우미는 사진 기준, 필요 자료, 표현 주의, 전문 의견 초안을 제공한다.
13. AI는 이미지 판독, 법적 책임 판단, 보증금 공제 판단을 하지 않는다.
14. 사진은 1차 구현에서 Base64 방식으로 첨부한다.
15. 최종 전문 의견은 시공업자가 검토·수정하여 작성한다.
16. 점검 제출 후 리포트를 생성한다.
17. 리포트 생성 시 임대인/임차인에게 자동 공개된다.
18. 임대인은 통합 리포트 리스트와 필터를 사용한다.
19. 임대인은 같은 호실 리포트 2개를 수동 비교할 수 있다.
20. 임차인은 본인 호실 리포트를 확인한다.
21. 임차인은 필요 시 의견을 남길 수 있다.
22. 임대인과 임차인은 확인 완료 처리를 할 수 있다.
23. PDF는 HTML 템플릿 미리보기 후 PDF 내보내기 방식으로 처리한다.
24. 공유 링크는 만료 시간 없이 계속 접근 가능하게 한다.
25. 작성 중/제출 완료 점검은 삭제 가능하다.
26. 생성 완료 리포트 삭제는 1차 구현에서 보류한다.
27. 생성 완료 리포트는 직접 수정하지 않고, 필요 시 새 리포트를 생성한다.
28. 리포트는 호실 기준 단순 누적 목록으로 관리한다.
29. 리포트 비교는 같은 호실 리포트 2개만 수동 비교한다.
30. 본 기능의 목적은 법적 판단이 아니라 시설 상태 기록, 공유, 분쟁 예방을 위한 증빙 정리이다.
